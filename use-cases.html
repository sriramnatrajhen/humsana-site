Use cases

Actions that are hard to undo.

If an action can be reversed with a second action, a log is usually enough. These are the cases where it cannot. The boundary is the same in every one of them. What changes is the action, and the fields that were bound when it was approved.

01

Payment releases

An exception sits in a queue after approval and is released later, sometimes the next morning. The account in the queue row is not the account that was approved.

The refusal names the account field and both values.

02

Beneficiary and vendor changes

A payee account is amended after approval. The instruction that reaches the executor is not the instruction the approver signed.

The refusal names the changed field and the rule that fixed it.

03

Regulated communication

A notice, a demand or a filing. The approved words and the recipient set both matter, and either can change between approval and send.

The refusal names the recipient set or the document that no longer matches.

04

Destructive actions

Deleting records, revoking access, closing accounts, destroying keys. There is no second action that undoes them.

The refusal names the scope the action had grown to.

05

Access and provisioning

An agent creates an account, grants a role or issues a credential. The grant was approved for one person and arrives covering three.

The refusal names the principal or the scope that changed.

06

Commitments

An agent commits the company to a purchase, a contract or a booking. The commitment is the action, and it outlives the session that made it.

The refusal names the amount, the counterparty or the term that changed.

What gets bound

An approval binds values, not intentions. The action class decides which values.

Field names and rules as the service applies them.

The action changes. The question does not.

Is this the action the principal authorized?

A grant answers it. The record proves the answer.

The same question holds whether the action moves money, sends a document, deletes a record, grants access or commits the company.

No grant. No execution.
