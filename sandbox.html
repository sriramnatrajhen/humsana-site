What happens

Four values, four outcomes.

The approved action is a payout release: £1,800 to Supplier X, account 4821, valid until 14:00.

Change the account to 9137 and press Execute. That is the whole demonstration: one approved action, one value moved, and a refusal from the live service.

Change the amount, the beneficiary, the account or the expiry. The page presents the action to the live service and shows the answer it returns.

Restore the approved value and the same action is allowed, once.

The sandbox demonstrates one action class. The calls are identical for every class the principal registers.

What the sandbox is.

No account and no login. Synthetic data only, and no money moves. Each run keeps its own state on the host for a short time so the page survives a reload.

The refusal you see is the service's own answer, not a scripted screen.

Where a confirmation is shown, the sandbox uses a reference confirmer and labels it as one. Authentication belongs to the principal's identity system: Humsana verifies the identity or assertion that system supplies, records who was authenticated and by which method, and binds the confirmation to the action.
