Use cases

Actions that are hard to undo.

If an action can be reversed with a second action, a log is usually enough. These are the cases where it cannot.

01

Payment releases

An exception sits in a queue after approval. The executor releases it later, sometimes the next morning. The account in the queue row is not the account that was approved. The release is refused, and the queue row keeps the reason.

02

Beneficiary and vendor changes

A payee account is amended after approval. The instruction that reaches the executor is not the instruction the approver signed. The changed field is named in the refusal.

03

Scheduled and batch actions

A batch is approved and sent later. A recipient is added, or an amount is raised, between approval and send. The batch no longer matches the approved one.

04

Regulated communication

A notice, a demand or a filing. The approved words and the recipient set both matter, and either can change after approval.

05

Destructive actions

Deleting records, revoking access, closing accounts, destroying keys. There is no undo, so the check has to happen before the action rather than after it.

The action changes. The question does not.

Is this the action the principal authorized?

A grant answers it. A record proves the answer.

No grant. No execution.
