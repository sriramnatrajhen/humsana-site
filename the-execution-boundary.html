The execution boundary.

Humsana is not trying to replace the identity system, the agent runtime or the executor. It sits at the point where a consequential action crosses from one authority context into another and asks whether the authority actually covers what is being executed.

Where it does not, the action is refused before the executor reaches the system that would perform it, and the refusal names the field, both values and the rule. Honoring that refusal is the executor's job, which is why the seam matters as much as the check.

Six stages carry authority to the point of execution.

Each stage can be checked, and each can be lost. The boundary's job is the fifth one: to know what arrives at the executor and whether it is still covered.

Where the boundary appears.

The action changes, the boundary changes, and the question stays the same: what authority actually covers this action?

Where it acts

Company A's agent → Company B's payment system.

What crosses

One company's agent instructs another company's payment system, and the instruction is a payment.

Where it acts

Company A's agent → a supplier's ordering system.

What crosses

An agent commits its principal to an order on a partner's system, where the terms were fixed earlier.

Where it acts

Agent → a system the customer does not own.

What crosses

An agent causes a consequential change in a platform it has no authority over, and the platform sees only an API call.

Where it acts

Autonomous workflow → another organization's action.

What crosses

One organization's autonomous workflow triggers an action inside another organization's operations.

Where it acts

Agent → agent → executor.

What crosses

Authority passes from one actor to another before execution, and each hop can narrow or stretch it.

What has to be true for this to matter.

  • 01The integrating party can place a check on the path that acts, on their side of the irreversible call.
  • 02An authority established for one system can be presented, and re-checked, in another.
  • 03A refusal at that seam is cheaper than reconstructing what happened afterwards.

Those three are the conditions an integration has to satisfy. The sandbox is the concrete part: one action class, the live service, no account and no login, synthetic data.
