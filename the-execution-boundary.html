The execution boundary.

Humsana sits at the point where a consequential action crosses from one authority context into another. It asks whether the authority still covers what is being executed, and refuses when it does not.

The refusal names the field, both values and the rule, and it spends nothing.

It does not replace the identity system, the agent runtime or the executor.

The same problem, at three depths.

One owner holds the actor, the tool, the rule, the approval and the request in a single log.

What one system settles

Identity, authority, the request and the approval sit under one owner, so nothing about the action is out of reach.

Nothing to carry

The authority context never leaves the system that issued it.

Identity travels between the two systems, but the authority for this specific action does not necessarily arrive with it. The approval stays in the system that made it.

What identity settles

Who the actor is. The authority behind the action is asserted by the calling system, not shown.

What has to be carried

The approval itself, or the executor is asked to trust that it exists somewhere in the company.

The executor holds the request and almost nothing else: not the principal, not the delegation, not the approval behind it.

What the request settles

That a request arrived. The counterparty's identity, policy and logs are not inspectable from here.

What has to be obeyed

A refusal holds only if whoever owns the executor obeys it. The other side cannot enforce it for them.
