When AI acts on your behalf, authority has to travel with the action.

An agent can have permission to act and still execute an action nobody approved. Humsana binds authority to the action itself, checks that action again before execution, and refuses it when it no longer matches.

Access tells you who can act. It does not tell you what this action was authorized to do.

An agent may have permission to call a payment API.

That does not prove that this payment, to this account, for this amount, was authorized.

That distinction matters when the action reaches the system that performs it.

Humsana checks the action there.

The check sits between the agent and the system that executes the action.

The agent presents the action to Humsana.

The executor checks the decision before acting.

For enforced action classes, no grant means no execution.
