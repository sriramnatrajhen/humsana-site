Developers

The integration is two calls and one rule.

The agent proposes an action. Humsana binds the authority to that exact action. Before the action runs, the executor checks it again.

No grant. No execution.

01 / The sequence

How a caller uses it.

01

Register the action class

The action class names which fields are bound, what consequence class it carries, whether a human step is required, and which executor checks the decision. Registration is data. The engine has no per-class code path.

02

Authorize the exact action

POST /v1/authorize with the principal, the agent, the action name and its parameters. The answer is one of the six decisions, the action digest, the binding and the expiry.

03

Confirm where the consequence requires it

The approving human is authenticated by the principal's identity system. Humsana verifies what it is handed and binds the approval to the action digest, not to a request.

04

Check at the seam, immediately before acting

POST /v1/authorize/effectuate with the receipt and the action the executor is about to perform. An exact match proceeds. A material change is refused, and the changed field is returned.

05

Keep the record

The receipt carries what was claimed, established, authorized, presented, executed or refused, the policy version, the action digest, the approving identity and the timestamps.

02 / The action class

One engine, any action the principal registers.

An action class is a registration: a name, the fields that are bound, a consequence class, and the rules that apply at execution.

The two calls are the same for every class. Nothing in the boundary is written per action type.

Action classFields carried in the binding
payments.releasepayee, account, amount, expiry
filing.submitdocument, recipient set, deadline

03 / The seam

The check has to be on the path that acts.

Humsana enforces at the execution seam controlled by the integrating party. The reference executor exists to demonstrate the seam and to be replaced by yours.

The boundary answers a question. The integrating party decides what happens when the answer is a refusal, and that decision is theirs to own.

// The executor presents the action immediately before it acts.

04 / The surface

What the service exposes.

EndpointPurpose
POST /v1/authorizePropose an action and receive a decision, a binding and an expiry.
POST /v1/authorize/effectuatePresent the action at execution and receive ALLOWED or REFUSED.
POST /v1/confirmRecord an approval bound to an exact action digest.
GET /v1/receipts/{id}Read the record for one authorization.
GET /v1/healthWhat the deployment is running: policy version, confirmation mode, router mode.
